How it works

Three steps. No file upload. The proof is mathematically verifiable by anyone, anywhere, forever.

1
Hash

The SDK computes a SHA-256 hash of the file on the user's device. The original file never leaves the browser or server.

Client-side
2
Sign

Evidencia signs the hash with an Ed25519 key pair and issues a timestamped receipt — the proof of existence.

Evidencia server
3
Verify

Anyone can verify the receipt against the public key — offline, in court, or via the verification portal.

Quickstart

Create your first proof in under 10 lines of code. 

import { Evidencia } from 'evidencia';

const client = new Evidencia({ apiKey: 'evd_sk_live_...' });

// Certify a photo from a file input
const file = document.querySelector('#photo').files[0];
const proof = await client.proofs.create({
  file,
  captureMethod: 'mobile_camera',
});

console.log(proof.id);                // "prf_01J4X9..."
console.log(proof.receipt.signature); // base64 Ed25519 signature
console.log(proof.receipt.timestamp); // "2026-03-14T10:42:00.000Z"
const { Evidencia, hashFile } = require('evidencia');
const fs = require('fs');

const client = new Evidencia({
  apiKey: process.env.EVIDENCIA_API_KEY,
});

// Hash a file and create a proof
const buffer = fs.readFileSync('./evidence.pdf');
const fileHash = await hashFile(buffer);

const proof = await client.proofs.create({
  fileHash,
  captureMethod: 'server',
  metadata: { caseId: 'INS-2026-4821' },
});

// Verify the proof
const result = await client.proofs.verify({
  proofId: proof.id,
  fileHash,
});
console.log(result.valid);                // true
console.log(result.checks.signatureValid); // true

API Reference

All endpoints accept and return JSON. Authentication uses Bearer token in the Authorization header.

Method Endpoint Auth Description
POST /v1/proofs API key Create a new proof from a file hash
GET /v1/proofs/:id API key Retrieve a proof receipt by ID
POST /v1/verify Public Verify a proof's signature and hash
GET /v1/publicKey Public Get the active Ed25519 public key
GET /v1/info Public API metadata and capabilities
GET /health Public Health check for monitoring

Receipt format

Every proof returns a self-contained receipt — a signed JSON object that can be verified offline without contacting Evidencia. 

{
  "schemaVersion": "1",
  "receiptFormat": "evidencia-receipt-v1",
  "issuedBy": "evidencia.tech",
  "proofId": "prf_01J4X9K2M8...",
  "fileHash": "sha256:e3b0c44298fc...",
  "hashAlgorithm": "sha256",
  "timestamp": "2026-03-14T10:42:00.000Z",
  "captureMethod": "mobile_camera",
  "signatureAlgorithm": "ed25519",
  "signature": "base64...",
  "publicKey": "base64...",
  "publicKeyId": "kid_01J4...",
  "metadata": {},
  "verificationUrl": "https://verify.evidencia.tech/prf_01J4..."
}
proofId Unique proof identifier (ULID-based)
fileHash SHA-256 of the original file, prefixed with sha256:
timestamp ISO 8601 UTC — when the proof was created
signature Ed25519 signature over the canonical signing payload
publicKey Base64-encoded public key for independent verification
metadata Optional key/value context provided by the caller
mediaRef Optional — durable media reference for B2B integrations

mediaRef — durable media references

The mediaRef field lets B2B clients attach a durable reference to the certified file — a claim number, a listing ID, or an article URL. It's stored in the receipt but never part of the signing payload. The cryptographic proof is always the file hash.

POST /v1/proofs — with mediaRef
const proof = await client.proofs.create({
  fileHash: 'sha256:e3b0c44298fc1c14...',
  captureMethod: 'mobile_camera',
  metadata: {
    mediaRef: {
      type: 'insurance_claim',
      claimId: 'CLM-2026-4821',
      storage: 's3://bucket/claims/CLM-2026-4821/photo_001.jpg',
    },
  },
});

JavaScript SDK

The official SDK handles client-side hashing, authentication, retries, and TypeScript types. Works in Node.js 18+ and all modern browsers.

<script>
  const client = new Evidencia({ apiKey: 'evd_sk_live_...' });
</script>
Method Description
client.proofs.create(params) Create a proof. Accepts file or fileHash, plus optional captureMethod and metadata.
client.proofs.retrieve(proofId) Retrieve a stored proof receipt by ID.
client.proofs.verify(params) Verify signature and optionally check file hash. Accepts proofId or inline receipt.
client.publicKey.retrieve() Get the active Ed25519 public signing key.
hashFile(input) Standalone SHA-256 utility. Accepts File, Blob, Buffer, ArrayBuffer, Uint8Array. Returns "sha256:<hex>".

Security

Evidencia is designed for cryptographic integrity from the ground up.

🔒
Ed25519 signatures
Every proof is signed with a 256-bit elliptic curve key. Signatures are deterministic and independently verifiable.
🧮
SHA-256 hashing
Files are hashed client-side using WebCrypto or Node.js crypto. The original file never touches the Evidencia server.
🔑
API key security
API keys are hashed with scrypt before storage. Raw keys are never persisted in the database.
🛡
No media storage
Evidencia stores hashes and receipts — never the original files. Your data stays on your infrastructure.
🌐
Content Security Policy
Strict CSP headers via Helmet. No inline scripts, no unsafe eval, no third-party trackers.
✅
Canonical signing payload
The signing payload uses deterministic JSON (sorted keys, RFC 8785 spirit). Changing a single byte invalidates the signature.
